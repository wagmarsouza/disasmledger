# Decompile3.0 — qualification history

The generic qualification core is in the [skill](../skills/decompile/SKILL.md), with the full
[contract/usage guide](../skills/decompile/references/generic-qualification.md).
This document records the local qualification that preceded the
[3.0 component release](release-decompile-v3.0.0.md). Publishing does not install tools
or automatically migrate existing missions.

New: fixed analytical/mechanical/recompilable/independent-validated categories; strict target
profiles; source-bound recovery review; six non-compensating gates; original/candidate/closure/
platform/tool/corpus bindings; ELF identity checks; approved external-verifier protocol with
fresh execution and bound construction/equivalence/control receipts; native Control8.4 bridge.

Preserved: completion.py, closure reports, grade ladder, stock/recon separation, live census
presentation, 8.2 inventory adapter, preservation witnesses, canonical binary identities,
renode-bench and binary-analysis-profile. No new ledger or scheduling engine.

Examples cover ARM Thumb C, native ELF x86_64 C, an external LLVM-equivalence adapter contract,
and analysis-only category. Profiles do not install their tools or supply a universal proof
solver. The C backend is executable for independent reconstruction; other categories/methods
need a separately approved target verifier. Finite tests, input tags and reviewer declarations
are not semantic truth or universal/hardware equivalence.

Run the new disposable integration pilot with the authorized Control8.4 CLI; no persistent
installation is needed. See the delivery's validation report and archive hashes for actual
executed checks and their limits. Do not treat earlier release notes as 3.0 test results.
