# Decompile 3.0 — generic qualification and target profiles

Authorized: implement D-a..D-f and the four application rules; preserve all existing behavior;
test inflation and generate updated local ZIPs. No installation, publication, live mission changes,
window closure or Claude changes. Base: published Decompile2.0 commit77767910b14b7ca9514dc16a5757977c835e379b.

## Contract

- D-a: effective target/unit-bound artifact. D-b: representation consistent with the declared category.
- D-c: explicit dependency/origin boundary. D-d: recovery integrity, no undisclosed placeholders.
- D-e: target-appropriate construction. D-f: bounded behavioral/equivalence evidence and controls.
- Categories are fixed before evaluation: analysis, mechanical-translation, recompilable,
  independent-validated. Only the final category with all six current gates qualifies the native
  reconstructed-unit counter. N/A/unknown never becomes a pass; no fallback/reclassification.
- Target profile is a pinned, strict document: architecture/endianness/ISA, language/backend,
  dependency/platform boundary, build format and validation method/observables/corpus requirements.
- C backend reuses completion.py rather than a second compiler/executor. Generic external verifier
  protocol supports other representations/methods through explicitly approved executable adapters;
  no universal C++/IR parser, emulator or equivalence solver is claimed or installed.
- Source-bound review records approved reviewer declaration, category, representation, completeness,
  unresolved operations and physically justified marker exceptions. Reviewer identity is not
  cryptographically authenticated. AST/regex are review aids, not universal readability proofs.
- Profile/contract/config are pinned before verification. Previous observations from another
  contract/profile are refused rather than silently downgraded. Explicit authorized mission revision
  and native pinned_roles govern adoption/change; no new approval flag or competing mission ledger.
- Every proof binds unit/source/review/transitive source dependencies/target/graph/profile/tool inputs.
  In-flight input drift refuses completion. Reuse requires current physical proof; selected audits
  force reexecution, exact recount and discriminating controls. No compensating scores.
- Existing completion, closure, preservation/inventory adapters, grade bars and sibling skills stay.
  Native Control8.4 owns closure/counting/history. New neutral reports use gates D-a..D-f and
  a per-unit qualification receipt; analytical/build milestones remain separate from qualification.

- [x] Q2: unchanged legacy suites, sibling suites, native-harness integration and real GCC pilot where

Limits: adopted verifiers/reviewers and input completeness remain trusted. Physical hashes do not
authenticate semantic honesty. Finite tests/profile obligations do not establish universal equivalence.
External proof must bind original and candidate; a proof about the candidate alone is insufficient.
