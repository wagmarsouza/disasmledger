# Decompile3.0 — local source review

Scope: fixed generic qualification categories, strict target profiles, source-bound recovery
reviews and approved target verifiers. No installation, remote write, live-mission migration,
new scheduler, competing census ledger or sibling-skill changes.

## Review axes

- Correctness: native wire formats remain unchanged; only independent-validated with all six
  current gates and a qualified dependency closure enters the reconstructed count. Native
  Control8.4 retains close/claim/history/audit authority. Invalid whole adapter frames refuse
  completion; individual incomplete proofs remain explicit unqualified units, never omitted rows.
- Architecture: CBackend reuses completion.Verifier; generic identity reuses binary_profile;
  one closure helper is shared. Existing completion/scheduling/presentation/inventory/preservation
  APIs remain. Generic receipts are evidence artifacts, not a second mutable mission store.
- Integrity: original/source/review/transitive source/platform/tool resources are physical refs.
  Category/profile changes refuse old evidence. External corpus and negative controls are fixed
  beforehand; source/build/original/proof/control/run/scope bindings are cross-checked. No shell.
- Readability: general requirements are in SKILL.md, exact contracts/limits in the generic guide;
  target examples expose assumptions rather than hardcoding project addresses or census sizes.
- Performance/bounds: explicit finite tool/check budgets, iterative dependency closure with
  cycle handling and freshness-based C reuse. External verifiers run fresh. No throughput claim
  for thousands of units; large targets need explicit budgets and complete input disclosure.

## Verification and limits

The original123 Decompile cases plus44 new cases passed in Windows and Linux. The preserved
40 Renode/25 identity tests also ran; Windows retains the existing symlink-permission skip.
Targeted guard inversions are sensitivity checks, not a global mutation score. Final native
pilot/distribution receipts live with the delivery, because extracted ZIP checks occur after
source freeze. Preserve intermediate diagnostic attempts rather than relabel them as success.

The real GCC pilot needed an explicit native toolchain budget instead of the 10s synthetic-tool
fixture cap; timeout remains a refused observation. No acceptance gate/control/corpus was weakened.
The resulting Linux native execution passed with actual GCC construction/process comparisons,
healthy and known-bad controls, live source/original invalidation, close and forced audit.

Trust boundaries remain explicit: reviewed dependency inventory, reviewer declarations and
approved verifier execution are trusted. A malicious verifier can lie; physical hashes cannot
authenticate semantic truth. There is no shipped universal LLVM prover, actual ARM/hardware
qualification or universal equivalence assertion. Finite inputs/scenario tags are not branch or
exhaustive semantic coverage. Global tools outside the project are rechecked at execution, not
continuously monitored by an unchanged nested receipt. Use project-bound freshness checks for
that requirement. Old APIs intentionally report declarations within their historical scope.
